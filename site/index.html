01 · The purpose

Research question and experimental sequence

Our research question is whether useful information remains in a model after deliberate unlearning. Low accuracy shows that the model no longer performs a task well. It does not show whether additional training could recover that task using information still stored in the model.

This report covers the preparation for that recovery question: establishing learning, measuring losses on earlier tasks, and testing deliberate unlearning against a learning-only control. It is an independent diagnostic study of the UnCLe method, not a complete reproduction of its paper.

Dataset and taskTiny ImageNet contains 200 image classes. We divide them into 20 tasks with ten classes each. Each task has 5,000 training images and 500 validation images. Task numbers identify groups of classes; they do not indicate difficulty or learning order.
Accuracy and score changeAccuracy is the percentage of validation images classified correctly. A change from 50% to 45% is a loss of five percentage points. Random guessing among ten classes has an expected accuracy of 10%.
Model and hypernetworkA neural network classifies images using numerical values called weights. Our hypernetwork generates those weights for a ResNet50 classifier, separately for each task. The predicted class is selected from that task’s ten classes.
Learning and unlearningLearning trains the model on a task’s images. Unlearning deliberately changes the model to reduce its performance on a requested task. Ordinary forgetting is an unintended score loss while learning another task.
Checkpoint and seedA checkpoint is a saved model that can be loaded as the starting point of a run. A seed starts a sequence of random choices, such as the order of training images. Using the same seed does not by itself guarantee identical GPU results.
Protection, beta, and epochProtection penalizes changes to the model weights generated for earlier tasks. Beta is the multiplier on this penalty. Beta 0 disables it. An epoch is one pass through a task’s training images. Each reported lesson uses five epochs.
ExperimentQuestionUse of the result

Why we checked Hyperfan initialization

Initialization chooses a model’s numerical values before training. The name is Kaiming, also called He initialization. In a hypernetwork, initializing the generator’s own layers does not by itself specify the starting scale of every classifier weight it generates. Hyperfan provides initialization rules for those generated weights. The UnCLe paper specifies Hyperfan to produce Kaiming-He initialized target parameters. Paper, learning method; Hyperfan reference.

The paired unlearning runner also resolved a difference between its two objectives: both the unlearning penalty and the old-task protection penalty now compare actual generated classifier weights, including scaling and offsets. Earlier unlearning results used a different representation and cannot be treated as results of this corrected runner. The detailed pilot uses a constant learning rate of 0.0001; differences from the paper are listed below.

How the hypernetwork produces an image classifier

The hypernetwork generates classifier weights from two short codes. A task code identifies which task the classifier will solve. A chunk code identifies which piece of the classifier’s weights to generate. Joining two 32-number codes gives a 64-number input. A chunk is a group of weight values, not a group of images.

ComponentRecorded architectureRole
Task code32 learned values per task.Selects a task-specific classifier.
Chunk codes200 codes of 32 values each, shared across tasks.Identify pieces of the generated parameters.
Shared hypernetwork layersFully connected layers: 64 → 128 → 256 → 512, with ReLU after each layer.Transform codes into features for the output heads. ReLU sets negative values to zero.
Output heads174 ordinary-weight chunks, two BatchNorm chunks, and 24 residual-projection chunks.Generate convolution/classifier parameters, BatchNorm scale/shift parameters, and skip-path projection weights.
Generated classifierModified ResNet50; 23,520,842 parameters per task.Weights are assembled from chunks, reshaped, scaled, and given the required offsets.
Hypernetwork size in the paired report134,016,154 parameters, including chunk codes and nine task codes after adding task 15.This count is separate from the generated classifier parameter count.

ResNet50 layers used in these runs

ResNet connects convolution blocks with skip paths that add an earlier representation to a later one. A projection changes the skip-path shape when needed. Our target uses Torchvision’s ResNet50 structure with a smaller first convolution and a ten-class output.

BatchNorm has two kinds of values: generated scale/shift parameters, which can change with the hypernetwork, and running means/variances stored separately for each task. Freezing the latter does not freeze all BatchNorm parameters.

Learning and unlearning objectives

Learning loss: classification error + beta × protection.

Paired unlearning loss: gamma × noise distance + protection.

Classification error is cross-entropy, which penalizes incorrect class predictions. Protection sums squared changes in generated weights relative to a frozen copy taken before the request, then averages over protected tasks. Noise distance averages the summed squared distance from task-3 weights to ten fresh Gaussian vectors with mean zero and variance one. Both objectives compare actual generated weights, including scales and offsets.

During unlearning, the seven tasks other than task 3 are protected. During later task-15 learning, all eight earlier tasks are protected, including task 3 at its post-unlearning state in B. Earlier-task training images are not replayed; protection uses generated weights. Gradients pass through the classifier to update the hypernetwork.

Sources: learning and protection code, paired unlearning code, and saved configuration and architecture measurements.

Without protection, the older-task average fell by 26.5 percentage points. Task 9 fell to 10.0%, and task 5 fell to 13.2%. With beta 0.1, the older-task average rose by 1.0 point and the largest individual drop was 0.4 points, while task 17 reached 50.8%.

We used beta 0.1 for the following sequence and pair, but did not establish it as the best value. The beta-0.01 row came from an earlier session, and each beta has only one result here.

Earlier one-seed pilot: task 3 stayed at 10% during task-15 training

Historical result from 7 October. The completed three-seed extension is shown at the top of this page; these older scores are not pooled into its averages.

Question: can deliberate unlearning reduce task-3 accuracy to chance, and does that accuracy increase again while learning a new task? Both branches loaded the checkpoint after task 14, containing tasks 3, 0, 9, 5, 17, 1, 7, and 14. The two branches ran in the same GPU session.

A · Learning-only controlSame starting checkpoint → learn task 15.
B · Unlearning branchSame starting checkpoint → unlearn task 3 → learn task 15.

A is the learning-only control: it measures changes caused by learning task 15. B adds task-3 unlearning before the same task-15 lesson. Neither branch used older-task training images. Older-task validation images were used only to measure accuracy.

To unlearn task 3, the runner changes its generated classifier weights toward fresh random noise while penalizing changes to the weights generated for the other seven tasks. This operation is intended to reduce task-3 performance. Its success is measured here by validation accuracy, not by a test of information removal.

07 · Interpreting the evidence

Comparison with the UnCLe paper: supported, mixed, and untested claims

The authors report chance-level forget accuracy, low damage to retained tasks, resistance to later relapse, and improved learning in longer sequences. They also report a membership inference test of privacy. Paper, discussion and Tables 1–3.

ClaimOur assessmentReason
Requested task falls to chanceSupported in six extension comparisonsTasks 3 and 14 reach 10% after forgetting in all three seeds. The earlier pilot also reached 10%.
No recovery during later learningSupported over one later lessonBoth forgotten targets stay at 10% after learning task 15 in every seed, with no recorded evaluation above the 12% threshold.
Other tasks remain stableMixed evidenceFinal mean losses were limited, but individual and temporary drops were larger.

Some implementation details, including classifier initialization and BatchNorm handling, remain documented reproduction choices rather than verified author settings. Paper, implementation and Appendix C.

Lessons from the completed experiments

  1. Ordinary learning can lower older-task scores. A learning-only control is necessary when measuring unlearning damage.
  2. Weight protection helped substantially in the beta trials, but one result cannot establish a stable optimum.
  3. Individual task scores and intermediate measurements provide information that averages and final scores miss.
  4. In six matched extension comparisons, the requested forgotten task stays at chance after one subsequent lesson. Other-task accuracy is not uniformly preserved.

Unanswered recovery question: can a small, fixed amount of additional training recover task-3 performance from the unlearned model? A control is needed because training can teach the task again, and information from other tasks can help. Recovery would need to show an advantage attributable to prior task-3 learning. This experiment has not been specified or run. The selected three-seed extension is complete; recovery remains untested.
