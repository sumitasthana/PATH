# Findings

What I set out to answer about UnCLe, what the paper claims and where it says so, what I measured, and how I reached the conclusion.

Paper: arXiv 2509.17530v1, "An Unlearning Framework for Continual Learning", Adhikari, Kumaravelu and Srijith. All page and section references below are to that version.

Last updated 28 October 2026.

A short note on the method, so the questions below make sense. A hypernetwork produces the weights of a second network instead of being the classifier itself. Each task has a code, called a task embedding, a learned vector of 32 numbers. The code goes in, a full set of classifier weights comes out. Forgetting a task means editing that mapping.

---

### 1. What does the forgetting step actually change?

Claimed: Methodology, "Unlearning", page 5. "A model that has unlearned a task is required to behave in a way that is similar to a model that has never been trained on that particular task. UnCLe realizes this goal by reverting the forget-task parameters generated by the hypernetwork back to a standard normal initialization."

Found: the task code is frozen and the shared generator is retrained, so that this one code stops producing a working classifier. The code itself is never touched.

How: the paper's own two algorithms show it. Algorithm 1, line 7, page 4, optimises both the generator and the task embedding when learning. Algorithm 2, line 8, page 5, optimises the generator alone when unlearning. My implementation matches, and so does the authors' released code, which hands the optimiser the hypernetwork parameters only.

A run then confirms what that implies. After forgetting I tried to relearn the task twice, once keeping its original code and once with a brand new code. The arm with the original code produced no response to its input for the first 38 steps. The arm with a new code responded within 2 steps. A second seed gave 50 to 60 steps against 0.

The split follows the code and nothing else. That is what you would see if the generator had been edited so that this one input now maps to dead weights. It is not what you would see if the code itself had been scrambled, since a scrambled code would behave like any other new code.

---

### 2. Does the forgetting objective make the weights random, or drive them to zero?

Claimed, in the main text: Abstract, page 1. "Tasks are unlearned by aligning the corresponding generated network parameters with noise, without requiring any data." Methodology, "Unlearning", page 5, says the same thing more fully: the hypernetwork "no longer generates meaningful parameters but rather noise that is akin to a randomly initialized network." Ablations, "Saturation Alleviation", page 7, goes further: the objective "restores the learned task-specific classifier parameters to a randomly initialized state, akin to a Kaiming He initialization."

Claimed, in the appendix: the opposite. Appendix E, "Connecting MSE and L2", page 11. "Minimizing the MSE term in the unlearning objective minimizes the L2-norm over the generated main network parameters, and consequently drives them toward zero."

Found: the appendix is right and the main text is wrong. The objective drives the generated weights to zero. Zero is not a randomly initialized network, so the method's headline description does not match what it does.

How: the paper proves the key identity itself, as Theorem 1, equation 7, Appendix E, page 12. Averaged over noise samples, the loss converges to the squared length of the generated weights plus a constant that does not depend on them. That quantity is smallest at exactly zero. Fresh noise is drawn every step, so there is no fixed random target to move toward.

So no new derivation is needed. The paper's own theorem says the objective is a noisy estimate of norm reduction, and its own appendix says norm reduction drives the weights to zero. The abstract, the methodology and the saturation argument on page 7 all describe a different end state.

My measurement separates the two. A model with random weights still reacts strongly to its input, just wrongly. A model with zero weights barely reacts at all. I measured how much the model's output moves across the test set, and after 100 forgetting steps it was 2.280e-06, which is effectively nothing. Random weights cannot give that number. Zero weights can.

### 3. What does the forgotten model actually output?

Claimed: Appendix E, "Connecting MSE and L2", page 11. "As a result, the model's logits for the unlearned task become zero across all output nodes, leading to a uniform distribution over classes. This corresponds to maximum entropy, indicating that the model is maximally uncertain about the forgotten task, precisely the desired effect of unlearning."

Found: that same zero-logit state, read as predictions rather than as a distribution, names one single class for every image. Exactly 10.00 percent on a balanced ten-class test set.

How: I ran the forgotten model over the whole test set and counted how many distinct classes it ever predicted. The answer was 1 out of 10, with 100 percent of predictions in that one class. Seen on two tasks of different starting strength, across several runs.

The accuracy is the giveaway. A model genuinely uncertain over ten classes would spread its predictions across all ten and land near 10 percent, but not on exactly 10.00, and the figure would wobble between runs. Exactly 10.00 percent with one class used is what you get when every logit is equal, the prediction rule breaks the tie the same way every time, and the model is right on that one class's share of a balanced set.

The paper and I are describing the same model. The difference is the reading. "Maximum entropy" sounds like ideal forgetting. Operationally it is a constant answer, and the 10 percent score is a tie-breaking artifact rather than evidence of a spread.

### 4. Do the paper's success tests show the task was removed?

Claimed: three results are offered as evidence of forgetting.

- Forget-task accuracy at or close to random. Discussion, page 6: "UnCLe achieves an FA equivalent or close to random, indicating complete forgetting of unlearned tasks." Table 1, page 6.
- Uniformity at 100. Table 8, UNI column, Appendix E, page 11, where UnCLe scores 100.0 on all four datasets.
- Membership inference at 50. "Membership Inference Attack", page 6: "A Membership Inference Attack (MIA) on UnCLe results in a score of 50%." Table 9, Appendix G, page 12.

Found: the constant-answer model from question 3 passes all three. So the tests show the model went quiet. They do not show the information is gone.

How: I took the model that question 3 produced and walked each test against it. Accuracy at chance is measured directly, and it is 10.00 percent, so that test passes. Uniformity scores the spread of the output values, and equal logits give a perfectly flat spread, which is why UnCLe scores exactly 100.0 rather than merely high. The membership attack works by spotting that a model responds differently to data it was trained on, and a model whose output barely moves with its input cannot respond differently to anything, so it passes too.

The paper's own Appendix G, page 13, says as much: "the forget head produces inherently random representations", and so "MIA performance remains equivalent across all methods."

All three are satisfied by a model that has stopped answering. None of them separates a model that forgot from a model that went silent. This point is not mine alone; Xu et al., arXiv 2505.16831, makes a version of it.

### 5. How many forgetting steps are actually needed?

Claimed: Appendix C, page 10. "We find that the burn-in of 100 is sufficient across datasets and we adopt it as standard in all our experiments." The same section adds annealing: "the burn-in rate is reduced by 10%, with a minimum of 20 iterations to ensure stability."

Found: the task is already at chance well before 100. The later steps do not remove more. They make the change harder to undo.

How: I forgot the same task three times from the same starting checkpoint, stopping at 6, 20 and 100 steps, then learned a later task and measured three things.

| Steps | Retained tasks after forgetting | Forgotten task after learning a later task | Input sensitivity after forgetting |
| ---: | ---: | ---: | ---: |
| 6 | 40.1% | 12.8% | 6.051e+00 |
| 20 | 39.4% | 10.0% | 3.943e-01 |
| 100 | 40.0% | 10.0% | 2.280e-06 |

Retained tasks stood at 40.4 percent before forgetting.

Read the three columns together. The first barely moves, so the extra steps are not buying safety for the other tasks. The second does move: at 6 steps the forgotten task climbs back to 12.8 percent once the model learns something else, above the paper's own relapse threshold, while at 20 and 100 steps it stays flat at chance. The third falls by six orders of magnitude, so the model goes from fully reading its input to not reacting at all.

So the extra steps are not removing more of the task. They are driving the model further into silence, where it can no longer drift back.

A separate measurement agrees. The generator's weights turn only 7.3 to 10.5 degrees from where they started by step 20, but 49.1 to 54.1 degrees by step 100, across three seeds. Most of the movement happens after the task has already stopped working.

### 6. Does forgetting damage the other tasks?

Claimed: Abstract, page 1. UnCLe performs its operations "with minimal disruption to previously acquired knowledge." The mechanism is the regularisation term in equation 3, page 5, which holds the retained tasks' generated parameters in place. Spill, equation 4, page 6, is the metric the paper introduces to measure this, and Table 2, page 7, reports UnCLe with the lowest spill by a wide margin.

Found: it holds. No measurable damage at any step budget.

How: the same three runs as question 5. The seven retained tasks averaged 40.4 percent before forgetting, and 40.1, 39.4 and 40.0 percent after it, at the three budgets.

Every gap is under one point, and I treat anything under three points as no difference, because repeated runs of the same setting vary by about that much. There is no trend with the step count either, so this is noise and not a small real cost.

### 7. Is the skill gone, or only blocked?

Claimed: Discussion, page 6. An FA at random indicates "complete forgetting of unlearned tasks". Methodology, page 5, sets the goal as behaving "similar to a model that has never been trained on that particular task."

Found: I could not determine this, and I do not think the question is reachable in my model.

How: two attempts, and the second is the more useful failure.

The first was a relearning test. If the skill is still in there, feeding the forgotten model a handful of images should bring it back faster than teaching the task to a model that never saw it. I gave both 1, 5 and 20 images per class and compared their best accuracy. On the first seed the forgotten model was ahead by 1.9 points, inside the three-point noise band, so it counts as a tie rather than a win. On the second seed it was behind by 2.8, 1.0 and 15.4 points at the three image budgets.

No advantage, then. But this test cannot prove absence either, because both sides train the generator, and training can rebuild a skill from scratch. A real gain would have been hard to see even if the skill were there.

The second was a reading test, designed to avoid that problem by training nothing. The idea: forgetting blocks one code, so give the model a different, unused code and see whether the task is still readable through it. I tried five random codes on the forgotten task.

The result was 10.0 percent, which is chance. But the control is what matters. I ran the same five codes on the model before any forgetting, when the task was sitting at 42.6 percent through its own code, and they read 9.5 percent. A task the model definitely knows reads as nothing through a random code.

So the probe cannot detect a skill that is present. It was dead before forgetting ever ran, which means the reading after forgetting carries no information at all. The test is void, not negative.

The paper's own numbers differ here. Table 8, Appendix E, page 11, includes a "Discard e_f" baseline, described on the same page as the case where "the forget-task's embedding is simply discarded and replaced with a random embedding", with no training at all. On Tiny-ImageNet it reports a forget-task accuracy of 15.54 percent, above the 10 percent chance level. My model gives chance in the same situation, and I do not yet know why.

### 8. How much of the method is new?

Claimed: Abstract and Introduction, pages 1 and 2, present UnCLe as a framework that unifies continual learning and unlearning without stored data.

Found: the architecture and the forgetting family are both cited prior work. What remains as the paper's own piece is the specific weight-space forgetting loss, which is the piece in question 2.

How: I matched each component of the method against the paper's own reference list.

The learning half is the hypernetwork continual-learning setup of von Oswald et al., ICLR 2020, cited in Methodology, "Learning", page 4. Appendix B, page 9, describes the rest of the architecture: a chunked generator with chunk embeddings and specialised output heads. The authors' released config uses 200 chunks and a 32-number task code.

The forgetting half belongs to an existing line of work that defines unlearning as making a model look untrained. The paper reviews it itself in Related Works, "Machine Unlearning", page 2, where BadTeacher (Chundawat et al. 2023a) "uses a random teacher network for the forget set", and GKT (Chundawat et al. 2023b) is also listed. Related Works, "Unified Solutions", page 2, cites UniCLUN (Chatterjee et al. 2024), by overlapping authors, which already "adapts BadTeacher to a continual setting".

Subtracting those leaves the weight-space forgetting loss, equation 3, as the new contribution. That is the part question 2 shows collapses to zero. BadTeacher defines forgetting on the model's outputs rather than its weights, which cannot collapse the same way, and UnCLe does not use it.

## Still open

Whether the task's information survives forgetting. Question 7 was meant to settle it and could not.

Why a discarded, randomly replaced code reads 15.54 percent in the authors' model and at chance in mine.

Whether an output-based forgetting objective avoids the collapse inside this architecture. Not yet run.

## How to read these numbers

Most results here are one seed unless stated. Where a second seed exists it is noted.

A forgotten task scoring above 12 percent after later learning has come back. That threshold follows the paper's own relapse metric, equation 5, page 6.

Differences under 3 points are treated as no difference, because repeated runs of the same setting vary by about that much.

Input sensitivity is the widest spread any single output score shows across the test set. It separates a dead model from one that is guessing but still reading its input. It is my measure, not the paper's.

Detailed dated records, including the runs that failed or were withdrawn, are in [docs/wiki/Experiment-trajectory.md](wiki/Experiment-trajectory.md).
